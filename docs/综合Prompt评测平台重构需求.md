# 综合 Prompt 评测平台重构需求

版本：0.2  
状态：第一阶段已实施，后续治理能力按本文继续扩展  
目标：将现有聊天室、Prompt Studio、记忆实验室和离线评测脚本重构为统一的团队协作评测平台。

详细页面流程、交互规则和边界状态见：[综合Prompt评测平台UX与交互设计.md](综合Prompt评测平台UX与交互设计.md)。

## 1. 产品定位

平台服务于多人 AI 角色扮演产品团队，用于管理 Prompt、设计受控实验、批量运行多人对话、执行 AI 与人工评测、分析回归、审批版本并发布到聊天室。

平台不是普通 Prompt 编辑器，也不是单纯的聊天演示页。它必须回答以下问题：

1. 哪个 Prompt、上下文策略、调度策略或记忆策略更好？
2. 提升来自哪个变量，是否经过控制变量实验验证？
3. 某次结论能否使用原始输入、模型参数和运行轨迹完整复现？
4. 新版本在哪些维度提升，在哪些场景回退？
5. 当前生产环境使用哪个版本，为什么允许发布，如何回滚？

从产品类型上看，它是一个面向多人角色对话的 **PromptOps / LLM 评测与发布治理平台**，由五类能力共同组成：

1. 资产管理：Prompt、变量、角色、世界观、模型、调度、记忆、测试集和评分卡。
2. 实验与评测：固定新旧版本对比、连续多人对话、自动生成、AI 评分和人工复核。
3. 数据分析：原始调用追踪、指标、案例、报告和回归分析。
4. 团队协作：成员、权限、评论、评审、任务和通知。
5. 生产治理：审批、发布门槛、生产快照、审计和回滚。

因此，除不可变的版本快照、原始运行证据和发布事件外，大部分业务资源都必须提供完整的增删改查和生命周期管理。

## 2. 当前问题

现有平台已有多人聊天室、三个固定 Builder 对比窗口、记忆双栏实验、Prompt 版本和 AI 十维评分，但仍存在以下结构性问题：

- 聊天室、记忆评测、Prompt Studio 和离线脚本相互割裂。
- Prompt、角色、世界观、历史窗口、记忆和调度规则没有统一版本快照。
- 固定多方案并排的概念增加理解和维护成本，实际需求只是比较旧版本与新版本。
- 当前工作台默认只有 4 个独立案例，无法代表 20/60 轮连续多人对话。
- 测试集、实验变量、重复次数和模型参数不能在 UI 中完整配置。
- AI 评分、规则检查和人工评审没有形成统一评分记录。
- 原始数据虽已开始保留，但运行级检索、筛选、导出和版本对比不足。
- 发布主要围绕 Prompt 文本，无法保证配套变量、角色、调度和记忆策略一致。
- JSON 文件适合原型，不适合团队并发、查询、审计和长期扩展。

## 3. 用户与权限

### 3.1 Prompt 设计者

- 创建 Prompt 和新版本。
- 编辑模板、变量协议和默认参数。
- 从旧版本建立分支。
- 发起实验并查看对比结果。

### 3.2 评测人员

- 创建测试集和连续对话脚本。
- 运行自动评测或进行真人体验测试。
- 标记 Good Case、Bad Case 和流程缺陷。
- 对 AI 分数进行复核或改分。

### 3.3 评审与负责人

- 查看版本差异和回归结果。
- 批准、驳回或要求修改。
- 配置发布门槛并执行发布、回滚。

### 3.4 管理员

- 管理成员、模型连接、预算、权限和数据保留策略。
- 查看任务队列、服务状态和失败原因。

首期可保留轻量身份体系，但数据模型必须预留团队、成员和权限边界。

## 4. 核心概念

| 对象 | 说明 | 关键要求 |
| --- | --- | --- |
| 工作空间 | 一个团队的评测空间 | 隔离成员、项目、模型连接和数据 |
| 项目 | 一个产品或 Prompt 评测目标 | 聚合 Prompt、场景、数据集、实验和报告 |
| Prompt | 可持续迭代的模板资产 | 支持标签、负责人、分支和版本 |
| Prompt 版本 | 不可变模板快照 | 保存变量协议、变更说明和来源版本 |
| 上下文方案 | 决定给模型注入什么 | 历史轮数、人设注入、最新消息、记忆上下文等 |
| 角色集 | 多角色配置 | 角色名、人设、类型、是否在场和版本 |
| 世界观 | 场景规则与背景 | 独立版本化，可被多个实验复用 |
| 调度方案 | 决定谁在什么时候发言 | 并行、串行、随机人数、@、主动线 |
| 记忆方案 | 记忆提取、更新、检索和注入策略 | 可与无记忆基线做隔离对照 |
| 模型配置 | 模型及采样参数 | Provider、模型、温度、惩罚项、超时和重试 |
| 测试集 | 可复用的测试输入集合 | 支持单轮案例和连续多轮剧本 |
| 实验 | 一组受控对比设计 | 包含基线、候选组、唯一变量和重复次数 |
| 运行 | 一次实际执行 | 保存完整配置快照、状态、成本和原始数据 |
| 评分卡 | 评分标准版本 | 维度、权重、锚点、封顶规则和上线门槛 |
| 报告 | 对运行结果的归纳 | 包含结论、图表、案例、原始数据引用 |
| 发布 | 生产版本快照 | 必须绑定完整配置，不只绑定 Prompt 文本 |

### 4.1 资源生命周期分类

平台中的资源不能统一使用一种“删除”和“编辑”规则，按审计要求分为四类：

| 类型 | 适用对象 | 更新规则 | 删除规则 |
| --- | --- | --- | --- |
| 可变业务资源 | 项目、标签、成员偏好、草稿、通知 | 允许原地修改，记录审计日志 | 进入回收站，可恢复 |
| 版本化资产 | Prompt、变量协议、角色集、世界观、模型配置、调度、记忆、测试集、评分卡 | 编辑草稿，保存后产生不可变版本 | 资产可归档；被引用版本不可物理删除 |
| 过程资源 | 评测定义、报告草稿、评论、人工评审草稿 | 在特定状态下可编辑，提交后锁定或产生修订版 | 软删除或撤销，不覆盖历史 |
| 不可变证据 | 运行快照、轮次、模型调用、原始回复、评分原文、发布与回滚事件 | 不允许原地修改，只能追加重试、修订或注释 | 默认不可删除；按数据策略整体清理并保留审计 |

| 角色 | 新建、复制、导入 | 列表、搜索、按性别/标签/状态筛选 | 名称、人设、头像、能力、状态 | 移出角色库、归档、恢复 | 历史运行保留原始角色快照 |
| 角色集 | 新建、复制、从房间保存 | 列表、详情、成员 Diff | 添加、移除、排序角色和配置在场状态 | 归档、恢复 | 被运行引用的版本不可修改 |

| 记忆方案 | 新建、复制、导入 | 列表、详情、检索与更新规则 | 提取、更新频率、Top K、注入模板和遗忘规则 | 归档、恢复 | 新旧版本评测默认共享同一版本 |
| 手工记忆 | 单条新增、批量导入 | 列表、关键词、角色、来源筛选 | 标题、内容、关键词、启停状态 | 删除、恢复 | 删除后不得继续注入 |
| 自动记忆槽位 | 新建槽位、复制 | 列表、命中和更新历史 | 标题、关键词、更新规则、启停 | 删除、恢复 | 系统更新内容保留修订历史 |

| 评分卡 | 新建、复制内置模板 | 列表、维度、权重、版本历史 | 维度、权重、锚点、封顶和门槛 | 归档、恢复 | 已用于运行的版本不可修改 |
| 评测定义 | 新建新旧版本评测、复制历史评测 | 列表、详情、状态、配置 Diff | 未启动前可修改版本、测试集和共享条件 | 删除草稿、归档历史定义 | 启动后冻结为运行快照 |

| 人工评审 | 新建评分、评论、复核任务 | 队列、详情、评审人、分歧 | 草稿可改；提交后用修订记录 | 撤回未提交草稿；已提交不可删除 | 支持仲裁 |
| 评论 | 新建评论、回复 | 按资源、状态和成员查询 | 作者编辑、解决、重新打开 | 作者软删除、管理员恢复 | 保留编辑记录 |
| 报告 | 新建、从运行生成、复制模板 | 列表、搜索、预览、关联运行 | 标题、人工结论、案例选择、展示配置 | 归档、回收站、恢复 | 数据区块更新产生报告修订版 |
| 发布申请 | 从候选版本创建 | 列表、详情、门槛和审批状态 | 提交前可改说明；提交后追加审批 | 撤回未审批申请 | 不能删除已完成审批记录 |
| 发布 / 回滚事件 | 系统创建 | 历史、详情、生产快照 | 不允许修改 | 不允许删除 | 回滚创建新事件 |
| 标签 | 新建、批量导入 | 列表、使用次数 | 名称、颜色、说明、合并标签 | 删除未使用标签、恢复 | 删除已使用标签前要求替换 |
| 保存视图 | 新建个人或团队筛选视图 | 列表、详情 | 名称、筛选、列配置和共享范围 | 删除、恢复 | 团队视图需要权限 |
| 导入批次 | 上传文件后创建 | 进度、映射、结果和错误 | 执行前可改映射 | 撤销整个批次 | 撤销不能破坏后续人工修改 |
| 导出任务 | 创建导出 | 进度、文件、数据范围 | 不修改已生成文件；可重新生成 | 删除过期文件 | 原始业务数据不随导出文件删除 |
| 团队成员 | 邀请、加入、批量导入 | 列表、权限、活动 | 姓名、角色、项目权限 | 移除、重新邀请 | 不能移除最后一名所有者 |
| 通知 | 系统创建或指派任务 | 未读、分类、资源关联 | 已读、置顶、订阅偏好 | 删除个人通知 | 删除通知不删除业务对象 |
| 审计日志 | 系统自动创建 | 按成员、资源、动作和时间查询 | 不允许修改 | 按合规策略归档 | 管理员也不能改写 |

### 4.3 CRUD 通用规则

所有可管理资源应遵循统一交互和 API 约定：

- 列表支持分页、搜索、筛选、排序、保存视图和列配置。
- 详情页展示基础信息、版本、引用关系、活动、权限和审计记录。
- 新建支持空白创建、复制已有资源、模板创建和导入。
- 编辑支持表单校验、草稿、乐观锁、冲突提示和离开保护。
- 删除默认进入回收站，不立即物理删除。
- 回收站显示删除人、删除时间、到期时间、依赖和恢复结果。
- 永久删除必须先解析完整依赖图，明确展示级联影响。
- 被不可变证据引用的资源不能通过级联删除破坏历史。
- 批量操作只作用于用户有权限的对象，并在执行前展示成功、跳过和失败数量。
- 所有写操作记录操作者、时间、变更前后摘要和来源。
- 所有创建请求使用幂等键，避免重复点击产生重复资源。
- API 支持统一的 `createdAt`、`updatedAt`、`createdBy`、`updatedBy`、`archivedAt` 和 `deletedAt` 字段。

## 5. Prompt 与变量管理

### 5.1 Prompt 编辑

- 编辑 Prompt 模板，支持变量高亮、搜索和格式化。
- 显示变量列表、来源、类型、是否必填和示例值。
- 实时报告未知变量、未闭合变量、重复段落和长度异常。
- 支持查看模板、变量值和最终渲染 Prompt 三种视图。
- 支持两版文本 Diff，区分模板改动与配置改动。
- 自动保存草稿，但只有“保存版本”才生成不可变快照。

### 5.2 变量类型

人为配置变量：

- `roleName`
- `rolePersona`
- `otherCharacters`
- `storyBackground`
- `taskDescription`
- `outputFormat`
- `dialogueRules`
- 角色集、世界观和触发线相关配置

运行时自动变量：

- `recentMessages`
- `latestMessage`
- `trigger`
- `mentionedCharacters`
- `allCharacterNames`
- `memoryContext`

平台需要展示运行时变量的生成规则。模型只接收替换后的内容，不应看到占位符。

### 5.3 版本能力

- 新建版本、复制版本、从历史版本建立分支。
- 查看任意两版差异。
- 切换当前编辑基线。
- 归档、恢复、发布和回滚。
- 版本必须记录作者、时间、变更假设、预期提升指标和风险。
- 已发布版本不可被原地修改。

## 6. 多人对话调度

调度方案必须独立于 Prompt，并作为实验变量和发布快照的一部分。

### 6.1 用户主动线

- 真人消息进入 3 秒打包窗口。
- 窗口内多名真人消息合并为一轮，窗口外消息形成新一轮。
- 每轮从可用 AI 角色中随机抽取 `1..N` 个角色，实际人数每轮可不同。
- 被抽中的角色必须回复，不使用 PASS。
- A/B 可并行生成，完整句生成后按完成顺序展示。
- 正在生成的角色不进入下一轮调度。
- 若玩家在生成期间发出新消息，新消息进入下一轮，不污染当前运行快照。

### 6.2 @ 唤起线

- 单 @：仅被 @ 角色回复，且必须回复。
- 多 @：所有被 @ 角色回复，未被 @ 角色保持静默。
- 已移出房间的角色不出现在 @ 列表。
- 前端支持 @ 按钮、输入 `@` 唤起和角色标签。
- @ 调度正确性单独计分，不能被文本质量高分抵消。

### 6.3 AI 主动线

- 房间内至少有真人在线才启动。
- 上一轮 AI 回复完成后开始计时。
- 默认间隔为 15 秒、30 秒，主动回复上限 2 轮；参数允许实验配置。
- 玩家一旦发言，立即重置主动线。
- 主动线沿用正常上下文和自然续写任务，不额外注入“冷场唤醒”Prompt。
- 主动回复不能覆盖正在处理的玩家消息。

### 6.4 双版本调度一致性

- 旧版本与新版本必须使用相同的角色抽取结果和调度顺序。
- 每个角色在两侧看到相同的历史窗口、玩家输入和在场角色。
- 调度方式、历史轮数和角色数量在一次评测中锁定，不能在两侧分别修改。
- 两侧分别保存每一步输入、输出、顺序、延迟和失败信息。
- 任一侧单个角色失败时保留失败记录，不使用另一侧结果替代。

## 7. 实验设计

### 7.1 评测类型

1. Prompt 新旧版本回归。
2. 真人连续多人对话体验。
3. 固定测试集批量回归。
4. AI 模拟玩家批量测试。
5. 世界观专项、角色边界专项、@ 专项、主动线专项和记忆专项测试。

所有评测最终都只比较两个对象：旧版本和新版本。

### 7.2 新旧版本对照

- 每次评测固定包含一个旧版本基线和一个新版本候选。
- 两侧共享测试输入、角色、世界观、模型、采样参数、调度、历史窗口和记忆配置。
- UI 必须明确显示两个版本的 Prompt 差异，并阻止其他配置出现意外差异。
- 相同输入按同一轮同时送入旧版本和新版本。
- 两侧共享相同的随机角色抽取结果，保证比较公平。
- 结论以旧版分数、新版分数、分数差和缺陷率变化为核心。

### 7.3 运行规模

提供清晰的运行预设：

| 模式 | 默认规模 | 用途 |
| --- | ---: | --- |
| 冒烟检查 | 4 个独立案例 | 快速检查服务和严重回归 |
| 快速体验 | 10 轮连续对话 | Prompt 调整后的即时观察 |
| 标准评测 | 20 轮连续对话 | 日常对比和案例分析 |
| 正式评测 | 60 轮及以上 | 发布结论和老板汇报 |
| 记忆评测 | 每案例至少重复 3 次 | 降低随机采样影响 |

开始运行前必须展示预计模型调用次数、预计耗时和预计成本。运行中展示已完成轮数、失败数和剩余任务。

### 7.4 输入来源

- 人工逐轮输入，适合真实体验。
- 固定测试脚本，适合回归。
- AI 模拟玩家，按目标和当前剧情动态生成下一条输入。
- 导入 JSON、CSV 或历史聊天室 transcript。

AI 模拟玩家不能预先写死全部输入，应基于上一轮实际回复决定下一步，并保存模拟玩家的生成依据。

## 8. 测试集管理

- 测试集拥有名称、描述、负责人、标签和版本。
- 支持单轮案例和多轮场景。
- 每个案例包含输入、前置上下文、期望、禁止行为和适用评分卡。
- 多轮场景包含世界观、角色集、玩家目标、停止条件和最多轮数。
- 支持按指令遵循、行动权、世界观、角色边界、@、主动线、记忆等分类。
- 支持从 Bad Case 一键保存为回归案例。
- 修改测试集生成新版本，历史运行继续引用旧版快照。

## 9. 评测体系

### 9.1 三层评测

1. 确定性规则检查：调度、@ 准确性、角色数、空回复、长度、问句、变量缺失和格式。
2. AI 评审：按评分卡逐条评分，返回维度分、缺陷标签、依据和引用片段。
3. 人工复核：评审者确认、修改分数、补充缺陷和选择 Good/Bad Case。

AI 分数不能覆盖流程错误。服务失败、解析失败和证据不足必须标记为待复核，不能伪造分数。

### 9.2 多人群聊评分卡

沿用现有 100 分十维标准：

| 维度 | 分值 |
| --- | ---: |
| 玩家指令遵循 | 15 |
| 当前相关性与连续性 | 10 |
| 玩家行动权 | 15 |
| 剧情发展合理性 | 15 |
| 剧情发展有趣性 | 10 |
| 人设遵循与角色边界 | 15 |
| 语气与风格差异化 | 5 |
| 世界观遵循 | 5 |
| 群像协作 | 5 |
| 表达与节奏 | 5 |

评分卡必须版本化，并保留高低分锚点、一票否决和封顶规则。

### 9.3 记忆评分卡

记忆能力与多人群聊质量分开评分，至少包含：

- 延迟事实回忆。
- 冲突消解与时效。
- 来源与角色归属。
- 遗忘与可控性。
- 检索精准度。
- 世界和角色状态连续性。
- 对玩家行动权的影响。
- 对角色边界的影响。
- 对回复长度、延迟和成本的影响。

记忆方案只有在记忆分显著优于无记忆基线，且多人群聊核心指标不回退时才可发布。

### 9.4 运行级指标

- 平均分、中位数、P10/P90 和分数分布。
- 玩家指令遵循率。
- 玩家行动权缺陷率。
- 角色边界缺陷率。
- 世界观违例率。
- @ 准确率。
- 选中回复完成率。
- 重复线索率。
- 问句滥用率。
- AI 淹没率。
- 事实矛盾率。
- 平均回复字数。
- 首字节和完整回复延迟。
- Token 与成本。

## 10. 原始数据与可复现性

每次运行必须保存不可变配置快照和每次模型调用的完整轨迹：

- 项目、评测、版本侧和运行 ID。
- Prompt、角色集、世界观、上下文、调度、记忆、测试集和评分卡版本。
- Provider、模型、温度、惩罚项、超时、重试和随机参数。
- 原始玩家输入、打包后的输入和触发线。
- 被选中角色、调度顺序和跳过原因。
- 注入的历史消息和记忆检索结果。
- 最终渲染 Prompt。
- 模型原始回复、清洗后回复和错误信息。
- AI 评分请求、评分原文和结构化分数。
- 人工评分、修改记录和评审意见。
- 每步开始时间、结束时间、延迟、Token 和成本。

原始数据默认不可编辑。人工修订以附加记录保存，不能覆盖原始结果。

支持 JSON、CSV、Markdown 报告导出。报告中的案例必须能跳回对应的原始运行和具体模型调用。

## 11. 可视化与分析

### 11.1 运行总览

- 运行状态、轮数进度、成功率、成本和耗时。
- 版本、模型、测试集和唯一变量摘要。
- 严重缺陷与发布门槛状态。

### 11.2 对比分析

- 旧版与新版总分和十维雷达图。
- 各轮得分折线图。
- 分数分布箱线图或直方图。
- 缺陷率、指令遵循率和行动权缺陷率柱状图。
- 延迟、Token 和成本趋势。
- 记忆命中、更新和事实冲突时间线。
- 新旧版本同输入回复的并排 Diff。

### 11.3 案例分析

- 自动筛选高分、低分、组间分差最大和评审分歧最大的案例。
- 展示同一玩家输入下各组回复、维度分和扣分证据。
- 一键标记 Good Case、Bad Case 或加入回归集。
- 支持按角色、触发线、场景、分数、缺陷和版本筛选。

### 11.4 报告

自动生成适合汇报的简版报告：

- 评测目标。
- 实验设计和控制变量。
- 样本量与模型配置。
- 核心结论和提升百分比。
- 各组指标表。
- Good Case、Bad Case、原因和修复建议。
- 风险、限制和是否建议发布。
- 原始数据链接。

## 12. 信息架构

统一为一个应用壳，不再把功能拆成互相孤立的独立产品。

### 12.1 一级导航

- 项目
- Prompt 资产
- 测试集
- 实验
- 运行记录
- 报告
- 发布
- 团队与设置

### 12.2 项目工作台

- 概览：最近实验、生产版本、风险和指标趋势。
- Prompt：编辑、版本、Diff 和最终渲染。
- 场景配置：角色、世界观、变量和模型。
- 实验设计：选择组、唯一变量、运行规模和评分卡。
- 实时运行：多栏聊天、进度、日志和人工输入。
- 分析：图表、案例、评分和原始数据。
- 评审：评论、审批、发布门槛。

### 12.3 实时对话工作台

- 左侧为场景、角色、调度和运行控制。
- 中间固定为旧版本与新版本两个横向窗口。
- 下方使用同一个玩家输入同时驱动各组。
- 右侧为本轮 Prompt、历史、记忆、调度、评分和错误详情。
- 页面不得自动抢滚动位置；新旧版本窗口独立滚动并提供“回到底部”按钮。

## 13. 发布与回滚

- 发布对象是完整运行配置快照。
- 发布前执行指定回归集和发布门槛。
- 门槛不通过时禁止普通发布，管理员强制发布需要填写原因。
- 发布页显示候选版相对生产版的提升、回退和高风险案例。
- 发布后保留生产快照、作者、审批记录和关联报告。
- 支持一键回滚到任意历史生产版本。
- 聊天室只读取已发布配置，不读取草稿。

## 14. 技术与非功能要求

### 14.1 架构

- 前端按项目、资产、实验、运行、分析和发布拆分模块。
- 后端将实时房间、实验编排、模型调用、评分和持久化解耦。
- 使用 Provider Adapter 兼容 DeepSeek、OpenAI 兼容接口及后续模型。
- 使用任务队列执行批量评测，支持并发限制、取消、重试和断点恢复。
- 实时状态通过 WebSocket 推送，持久数据通过 REST API 管理。

### 14.2 数据

- 从 JSON 文件迁移到数据库。
- 本机开发默认 SQLite，团队部署支持 PostgreSQL。
- 使用数据库迁移脚本，保留现有 `config.json`、工作区和历史评测数据。
- 所有文本统一 UTF-8。
- 时间以 UTC 存储，前端按用户时区显示。

### 14.3 稳定性

- 服务重启后运行状态可恢复或明确标记中断。
- API 请求使用幂等键避免重复创建运行。
- 单次模型失败不导致整批数据丢失。
- 清空会话创建新 Session，不复用旧历史、旧记忆或待完成请求。
- 所有删除操作有确认和可恢复策略。

### 14.4 可迁移性

- 不依赖固定 Windows 路径。
- 配置通过环境变量和项目设置注入。
- 文件导出使用跨平台路径和标准格式。
- 本地、服务器和容器环境使用同一套业务逻辑。

### 14.5 成本与安全

- API Key 只保存在服务端，不进入前端、日志或导出文件。
- 运行前提供调用量和成本预估。
- 支持团队预算、单次运行上限和模型并发上限。
- 原始数据可配置脱敏和保留期限。

## 15. 分阶段范围

### 第一阶段：统一底座

- 新数据模型和数据库迁移。
- 统一应用壳、项目和一级导航。
- Prompt、变量、角色、世界观、模型和评分卡版本化。
- 将现有 Prompt、测试集和历史运行迁移为旧版资产和历史记录，不在新产品中继续暴露固定方案编号。
- 原始模型调用完整留档。

### 第二阶段：实验闭环

- 实验设计器和控制变量校验。
- 4/10/20/60 轮运行预设。
- 单轮、连续多轮、人工输入和脚本输入。
- AI 评分、规则检查、人工复核。
- 对比图表、案例分析和数据导出。

### 第三阶段：多人调度与记忆

- 三条发言线编排器。
- A/B 并行和 C 串行。
- 记忆方案版本化、无记忆对照和记忆专项评分。
- AI 模拟玩家和重复实验。

### 第四阶段：团队发布

- 团队身份与权限。
- 评论、审批和评分分歧复核。
- 发布门槛、生产快照和回滚。
- 报告模板、分享和审计日志。

## 16. 首期验收标准

1. 能从任意旧版本创建新版本，查看 Diff，并随时切回旧版本。
2. 能创建一个旧版本与新版本的 20 轮连续对比评测。
3. 能锁定角色、世界观、模型、历史窗口、调度和记忆配置，只允许 Prompt 版本不同。
4. 能使用同一组实际玩家输入驱动旧版本和新版本。
5. 每轮能正确记录角色抽取、并行或串行顺序、最终 Prompt 和原始回复。
6. AI 评分覆盖既有十维标准，流程缺陷与文本分分开呈现。
7. 任一图表和报告案例都能追溯到原始模型调用。
8. 能对比无记忆和有记忆条件，并检查群聊指标是否回退。
9. 能在发布前看到候选版相对生产版的提升百分比和 Bad Case。
10. 发布只影响生产聊天室，草稿和实验运行不污染线上配置。
11. 服务重启后版本、测试集、运行、评分和报告仍然存在。
12. 原有 Prompt、角色、世界观和历史评测数据迁移后可继续读取。

## 17. 暂定产品决策

以下决策先作为推荐默认值，进入详细设计前需要确认：

1. 首期以单团队工作空间为主，数据模型保留多团队能力。
2. 本机使用 SQLite，部署环境支持 PostgreSQL。
3. 默认评分为规则检查加 AI 评审，正式发布要求人工复核高风险案例。
4. 默认冒烟 4 例、标准 20 轮、正式 60 轮。
5. 原始数据长期保留，删除运行采用软删除。
6. 报告首期支持 Markdown、JSON 和 CSV，后续增加 PDF。
7. 当前多人聊天室保留为生产体验入口，但配置和运行数据改由新平台统一管理。
